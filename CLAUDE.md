# SpeechChem — Accessibility Mod for SpaceChem

Screen-reader accessibility mod for blind players of SpaceChem (Zachtronics, 2011). Bootstrapped
2026-09-26/27 from Echopunks (`../exaaccess`, the EXAPUNKS mod) — same host/module architecture,
typed-game-access pipeline, graph UI and dev tooling. Read Echopunks' CLAUDE.md for the long history
behind the shared pieces; this file records what is DIFFERENT here and what has been verified.

## 1. Game facts (all verified live or in the decompile)
- **Engine**: Zachtronics' own "Impeller" engine (namespace `Impeller`) over SDL2 + OpenGL, NOT
  Unity. `SpaceChem.exe` is one **x86 (32-bit)** .NET assembly built for **CLR 2.0**
  (`supportedRuntime v2.0.50727`). Deps next to it: SDL2/SDL2_image/SDL2_mixer (x86), sqlite3 +
  System.Data.SQLite 1.0.66, Newtonsoft.Json 3.5, Ionic.Zip, Mono.Security, steam_api.dll.
- **Install**: `C:\Program Files (x86)\Steam\steamapps\common\SpaceChem`. Steam appid **92800**
  (`Class47.uint_0`); `Program.Main` calls RestartAppIfNecessary, so `steam_appid.txt` sits in the
  game folder (build writes it; Bootstrap re-writes as fallback).
- **CLR 4, not 2**: our `deploy/SpaceChem.exe.config` REPLACES the stock config (the only game file
  we overwrite; the Debug deploy keeps the pristine copy as `SpaceChem.exe.config.vanilla`). It
  selects CLR 4 (the game runs unchanged on it — `clr.dll` 4.0.30319 verified loaded) so net48,
  Harmony 2.4.2 and Mono.Cecil work.
- **TWO APPDOMAINS**: `Program.Main` with no args only configures sqlite, then loops
  `CreateDomain("SANDBOX")` → `ExecuteAssembly("SpaceChem.exe", new Evidence(), "--game")` → unload,
  repeating while the game returns 1 (its in-game restart). The game lives in SANDBOX. Consequences:
  - The AppDomainManager is instantiated in EVERY domain (verified): the default-domain instance only
    truncates the log; each SANDBOX instance boots the mod and tears it down on DomainUnload (speech,
    dev server port, module Dispose). A game restart = a fresh mod generation in a new domain, log
    appended.
  - That ExecuteAssembly overload takes Evidence, which CLR 4 rejects (NotSupportedException, "implicitly
    uses CAS policy") unless `NetFx40_LegacySecurityPolicy` is enabled — verified both ways (without it
    the process exits with code 1 before the window opens). Hence that switch in the config.
  - Inside SANDBOX the game assembly is not loaded when the domain is created: Bootstrap hooks on the
    `AssemblyLoad` event for "SpaceChem" (still before its entry point runs).
- **Obfuscation**: Eazfuscator.NET, harder than EXAPUNKS: TYPES are renamed too (only ~190 of ~1300
  keep real names: `SpaceChem.Program`, the `*Editor` screens, `SpaceChem.Reactor.*`,
  `SpaceChem.Pipeline.*`, `Impeller.*`), members are `#=q…`, and EVERY type is `internal`.
- **Boot splash**: NOT a click gate (unlike EXAPUNKS). `Class185.vmethod_14` draws the Zachtronics
  intro; Space/Escape/click skip it and it advances on its own; then the texture-load bar. Ticks start
  only after it (init = `Class185.vmethod_2`).

## 3. Typed game access (the remap pipeline, extended for SpaceChem)
Same idea as Echopunks: the MODULE compiles against deob names; the host rewrites the module's game
references to shipping names at load (Mono.Cecil, `src/Modularity/GameRefRemapper.cs`) using
`namemap.tsv`. Assembly name is "SpaceChem" in both binaries. Three SpaceChem-specific additions:
- **NameMap** (`tools/NameMap`): row-order alignment of orig vs deob as before, plus (a) nested types
  that KEEP their name under a RENAMED parent are compared through the parent's pairing
  (`#=qG74…/EyeColor` = `Class311/EyeColor` — the first alignment run died on it), and (b) a
  structural cross-check: every pairing whose base class is in-assembly must pair that base too.
  Current result: 1308 type pairs, 178 name anchors, 325 base checks, 15 junk rows skipped (three
  clusters of Eazfuscator runtime types), ~12k renames, no member drift.
- **Publicize** (`tools/Publicize`): the module references `game/SpaceChem-deob.ref.exe`, the deob exe
  with every type/member made public (explicit interface impls excepted) — regenerated by the module
  build when the deob exe changes.
- **IgnoresAccessChecksTo**: `module/src/AccessChecks.cs` declares
  `[assembly: IgnoresAccessChecksTo("SpaceChem")]` (+ the attribute class). The .NET Framework 4.8
  CLR honors it: verified first with a two-assembly experiment (internal type, private method), then
  live — the byte-loaded module under legacy CAS patches and calls internal/private game members.
  So module code reads like plain C#: `Class53.smethod_0()`, `card.timeSpan_0`, `story.float_0`,
  private statics as Harmony targets via `Expr.MethodOf(() => Class152.smethod_11(...))`. `Deobf`
  (namemap by string) is now only needed for reflection-by-name.
- **The HOST** has no compile-time game reference and SpaceChem's engine types are renamed, so it
  resolves through the same map at runtime: `src/GameNames.cs` (deob → shipping types/members, plus
  reverse lookups for dev dumps). No map = no hooks and no module (loudly logged).

## 4. Engine decoded (the load-bearing facts; details in game/decompiled)
- `Class184` — abstract engine game: SDL window/GL context (`method_1`), main loop (`method_7`:
  event pump `method_17` → `vmethod_3` update → `vmethod_4` draw → swap, ~15 ms sleep), splash loops
  (`method_6`), transitions (`method_8(Interface1)`/`method_9()` run their OWN blocking draw loops —
  no update ticks during a transition).
- `Class185 : Class184` — SpaceChem's game. HOST HOOKS: `vmethod_2()` postfix = init done (builds
  `MainMenuEditor` as the root screen); `vmethod_3(Struct102)` prefix = per-frame tick. Global
  `Class280.class185_0` = the instance; `Class280.struct102_0` = the frame clock (`timeSpan_0` total,
  `timeSpan_1` delta).
- **Screens** = "editors", base `Class53`, a doubly linked CHAIN (not a list): static `class53_0` =
  root, `class53_1` = parent (below), `class53_2` = child (above). `smethod_0()` = top,
  `smethod_1(s)` = push on top, `smethod_2()` = pop top, `method_1(null)` = detach self (how cards
  dismiss themselves), `smethod_7()` enumerates top-down. `vmethod_2(Enum109)` = per-frame update,
  `vmethod_3(SpriteBatch)` = draw. `Class54 : Class53` = widget-tree editors (`GClass8` tree,
  `CompositeWidget`, buttons from `Class203.smethod_4/5/7`) — promising for a generic reader.
- **Widget screens rebuild on regaining the top**: `Class54.method_6` runs `vmethod_5` (for
  TitleScreenEditors: rebuild the whole widget tree from `vmethod_8`) the first update after the
  screen becomes the top again; `Class54.bool_1` = "built since regaining the top". A rebuild makes
  NEW widgets (the profile-name field comes back empty after the game's error box). Modeled screens
  over Class54s read only once `bool_1` is set (`ProfileUi.Settled<T>`).
- **Input facade** `Class259` (static, per-frame snapshot): `bool_0` = left mouse pressed this frame,
  `bool_4` = left held, `bool_8` = right held; `smethod_3/4(Keys)` = just pressed, `smethod_5(Keys)`
  = held. `Impeller.Keys` values are **SDL SCANCODES** (Enter 40, Escape 41, arrows 79–82).
- **Widget key path** (the second channel): the event pump calls `Class185.vmethod_9/10/11`, which
  forward to the top Class54's `method_9` (press, with repeat flag) / `method_10` (release) /
  `method_11` (character from SDL_TEXTINPUT). They queue into its `GClass8` widget tree: a press goes
  first to the SCREEN's `imethod_0` (TitleScreenEditor dialogs: Escape = cancel; the message box
  `Class71`: Escape/Enter = close), then to the focused widget (`GClass16` text field: Enter =
  submit, Backspace = delete, 12-character cap, font-filtered characters). `GClass15` buttons are
  mouse-only: press = `Class428.class14_4` click sound + the action.
- **Localization**: `Class323.smethod_0(key)` / `smethod_1(key, comment)` → `Class239` tables
  (`lang\<code>`); keys are the English text; display-font strings pass the comment
  "ENGLISH ALPHABET ONLY". Story/journal prose: `Class177.smethod_1()[sectionKey]` →
  `Class248(string_0 title, string_1 body)` from `text\<lang>.text`.
- **Profiles**: `MainMenuEditor.vmethod_4` auto-selects the first profile of `Locals.smethod_5()`
  (a HashSet of `Class436`: `string_0` name, `method_0()` rank int → `((Enum105)r).smethod_1()` rank
  title, `method_2()` last played); only with NO profile does it push the picker `Class75`. Otherwise
  the picker opens from the main menu's "Switch Profile" (`MainMenuEditor.method_25`). See §10.

## 5. Build & deploy
```
dotnet build            # or .\build.ps1 (locates the game; SPACECHEM_DIR overrides)
dotnet test
.\build_release.ps1     # releases\SpeechChem-vX.Y.Z.zip (version in Directory.Build.props)
```
Everything is **x86** (host, module, tests — the module references the 32-bit game, so the test
host must be 32-bit too). BUILD PREREQUISITE: `game/SpaceChem-deob.exe` (run `tools\prepare-game.ps1`).
A Debug build deploys: `SpeechChem.dll`, `SpeechChem.Module.dll`, `0Harmony.dll`, `Mono.Cecil.dll`,
`prism.dll` (x86), `SpaceChem.exe.config`, `Mono.CSharp.dll` (dev REPL), `steam_appid.txt`,
`SpeechChem\namemap.tsv`, `SpeechChem\locale\`. The host dll is file-locked while the game runs; the
module is not (hot reload). Uninstall = restore `SpaceChem.exe.config.vanilla` over the config.
Release zip = the same set minus Mono.CSharp. `create-release.ps1 vX.Y.Z` = gh release (the installer
exe is optional — the Rust installer has NOT been ported yet; Echopunks' `installer/` is the source).

**Prism x86**: upstream publishes Windows x64/arm64 only. `third_party/prism/x86/prism.dll` is our
own Win32 build of v0.16.6 (commit 655fb40, the exact version of the vendored x64 dll and header;
static CRT; 42 undecorated cdecl exports) — `third_party/prism/x86/BUILD.md` has the recipe.
Verified live: Prism picks NVDA in-process. `PrismNative` MUST declare
`CallingConvention.Cdecl` (the x86 P/Invoke default is StdCall).

## 7. Dev loop (DEBUG builds)
The dev server starts with EVERY launch of a Debug build (a plain Steam launch included —
user decision 2026-09-27); `SPEECHCHEM_DEV=0` turns it off. Release builds contain none of it.
Loopback server on `127.0.0.1:8773` (`SPEECHCHEM_DEV_PORT` overrides; WotR 8771, Echopunks 8772):

| Route | Purpose |
|---|---|
| `GET /health` | liveness |
| `POST /say` | speak the body through the real speech path |
| `GET /speech?since=N` | what the mod has spoken since cursor N |
| `GET /screen` | the game's screen chain, bottom → top, by DEOB type name |
| `GET /gui` | reflection dump of the top screen: fields in token order as `f[N] deobName : DeobType` |
| `GET /screenshot` | PrintWindow capture to `%LOCALAPPDATA%\SpeechChem\screenshots\` (no focus change) |
| `POST /eval` | C# against the live game (SHIPPING names only — it cannot name deob types) |
| `POST /reload` | hot-swap the module from disk (build the module with the game running first) |
| `POST /probe` | `command [arg]` → the live module's typed `SpeechChem.Dev.Probe` (DEBUG only) |

Probe commands: `screens` (chain + modeled screen + focused node), `push shiplost|credits|epilogue`,
`pop`, `key <action id>` (dispatches e.g. `ui.down`/`ui.activate` through the navigator exactly as the
key binding would — no window focus needed), `click` (synthetic left click), `type <text>` (one
SDL_TEXTINPUT event — the game's real typing path; the navigator's echo sees it), `rawkey <scancode>`
(a raw SDL key press to the GAME only — the mod's input reads SDL's state array, which pushed events
don't update; use it to test what the game receives, e.g. that suppression blocks Enter),
`profiles` (the profile set, `*` = current), `switchprofile` (main menu's Switch Profile).
Profile tests WRITE THE SAVE DATABASE (`%LOCALAPPDATA%\Zachtronics Industries\SpaceChem\.locals`):
create throwaway profiles and delete them again. Grow it with each screen
(Echopunks' AuditProbe is the model). `/eval`, `/screen`, `/gui`, `/probe`, `/reload` run on the main
thread (pumped from the tick), so they time out during the splash and transitions.

## 8. Architecture
Host (`SpeechChem.dll`, `src/`): `Bootstrap` (AppDomainManager; see §1), `GameNames` + `GameState`
(runtime name map; the screen chain; hook MethodInfos cross-checked by signature),
`Patches/GamePatches` (init postfix + tick prefix, applied once per domain), `Modularity/`
(IModModule contract, byte-loading ModuleLoader, GameRefRemapper), `Speech/` (Prism → SAPI →
clipboard chain, `Tts` chokepoint; `speech.output` in `%LOCALAPPDATA%\SpeechChem\settings.json` or
`SPEECHCHEM_SPEECH`), `Dev/` (DEBUG only), `Log`, `HostConfig`.

Module (`SpeechChem.Module.dll`, `module/src/`, hot-reloadable): `SpeechChemModule` (composition
root; ALL game patches arm on the FIRST TICK, never in Load — patching runs the target type's cctor;
see Echopunks' 2026-08-23 cold-boot crash), `FrameLoop` (keyboard → input → loc → screens → click
release), `Localization/` (Loc.T + ui.json), `Input/` (SDL keyboard snapshot, bindings, OS repeat),
`UI/Graph/` (the WrathAccess key-graph core, BCL-pure, verbatim with its tests), `UI/` (GraphNavigator,
Navigation, ControlTypes, ScreenNames — strips `Editor`/`Screen` suffixes; curated labels in ui.json),
`Screens/` (Screen + ScreenManager poll-and-diff; unmodeled screens announce by friendly name,
obfuscated names never spoken), `Game/` (GameText, GameApi, SdlNative, SyntheticClick, Deobf/Expr),
`Patches/` (GameKeySuppression, GateTextCapture), `Update/` (launch update check against
`amerikrainian/speechchem` releases — 404s until the repo has a release; log line only), `Dev/Probe`.

SCREEN-SCOPED ACTIONS: any input action id starting with `screen.` is dispatched to the focused
screen's `GetActions()` (GraphNavigator's default branch). This replaced Echopunks' explicit
whitelist, whose missing entries silently swallowed bindings.

## 9. Click-anywhere gates (`module/src/Screens/ClickGateScreens.cs`) — verified live
Full-screen cards that advance on ANY left click (no hit test) and read no keys. Each is a tiny graph:
drawn text as read-only rows (spoken as they APPEAR — cards reveal text on timers — and re-readable
with arrows), then a Continue button labeled with the game's own "Continue". Continue replays the
game's advance through SDL: `SyntheticClick` pushes SDL_MOUSEBUTTONDOWN (button 1) and the UP two
frames later (position is irrelevant: the engine tracks the cursor from motion events).
- `ShipLostScreen` — deob `Class154` ("{ship} has been lost." at 5 s, "click to continue" at 7 s;
  ship = `Levels.dictionary_2[enum147]`, or "The Prometheus" for value 8). Probe-pushed, read
  (matches the pixels), dismissed through the game's own transition.
- `CreditsScreen` — deob `Class152` cards run by `Class153`; card strings captured by
  `GateTextCapture` (postfix on `Class152.smethod_11`, lines ordered by drawn y). All 8 cards
  announced; Continue skips a card; the sequence ends cleanly.
- `EpilogueScreen` — deob `Class81` ("CLICK TO SCROLL STORY"): scrolls while the button is HELD and
  pops once scrolled past its end. Its section keys are captured around `Class81.smethod_13/12`; rows
  are the story bodies from `Class177`. Continue sets `float_0` past the end so the card's own next
  update pops it. All 9 sections read; finish verified.

## 10. Profile flow (`module/src/Screens/ProfileScreens.cs`) — verified live 2026-09-27
Four TitleScreenEditor overlays, all gated on `ProfileUi.Settled<T>` (see §4) and all with Escape
native. Buttons replicate the GClass15 press (click sound + handler).
- `ProfilePickerScreen` over `Class75` "Select a User Profile": three slot rows, each speaking its
  own "n of 3" (SpeaksOwnPosition — the builder would count a row's cells, or the New Profile rows
  among themselves). Profile slot: "name, button, rank, Last Played: date"; Right = the drawn X as a
  "Delete" button (mod label — the X is a pictograph), also Backspace on the slot; Enter = the game's
  select (`method_20`: make current, load, close → "Main menu"). Empty slot: "New Profile"
  (`method_18`). First three profiles in the live set's enumeration order, like the draw.
  KeepStateOnPop, so focus survives the dialogs.
- `NewProfileScreen` over `Class72`: the field is a TextEntry node over the game's GClass16
  (TextIdentity = the widget instance, so a rebuild re-baselines instead of echoing a deletion);
  typing and Backspace reach the game natively; one vertical column with no counts (name → Create
  Profile → Cancel → notice; user layout). Enter on the field or "Create Profile" = `method_19`
  (validates; empty/duplicate names open `Class71`, then the game REBUILDS the dialog, clearing the
  field — faithful). Cancel = `method_18`. The public-name notice is a text row.
- `DeleteProfileScreen` over `Class73`: focus starts on Cancel; "Delete Profile" = `method_19`
  (the game renames the save to `NNN.user-deleted`).
- `TitleMessageScreen` over `Class71` (any title-screen message box): arrival speaks title + text,
  focus on Okay.
- SUPPRESSION SEAM 2 (`GameKeySuppression`): a prefix on `Class54.method_9` drops our nav keys before
  the widget queue, so Enter never acts twice (the field's own Enter would create the profile, then
  ours would hit "already exists"); Backspace passes both seams while a TextEntry node is focused.
  Verified with `rawkey`: raw Enter blocked, raw Backspace deletes a character.

## 11. Hard rules (inherited from Echopunks — same reasons)
- Never commit or ship game code or anything derived from the game's binaries (`game/` stays
  gitignored); the shipped namemap carries name pairs only.
- Never crash the game: every hook body catches everything; Bootstrap swallows everything.
- Read the model, never the pixels.
- Game access is typed through the remap pipeline; never string-based reflection with deob names
  (it does not remap) — `Deobf` or `Expr.MethodOf`.
- Never speak `#=q…` or deob names like `Class75` — ScreenNames filters.
- Localize every string the mod speaks (`Loc.T` + `module/assets/locale/enGB/ui.json`); never duplicate
  a string the game has (`Game/GameText`); no mod-authored hints.
- Speech never interrupts by default; everything goes through `Tts.Speak`.
- All dev tooling is `#if DEBUG` and loopback-only.
- `AssemblyVersion` stays 1.0.0.0 unless `deploy/SpaceChem.exe.config` changes in the same commit.
- Keep `module/src/UI/Graph` BCL-pure.
- Never apply a game Harmony patch before init (first-tick arming).
